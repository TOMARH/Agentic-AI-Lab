# ADR 0005: Route BlobCreated events through Event Grid to the existing Service Bus queue

- **Status:** Accepted
- **Date:** 2 October 2026
- **Context:** The lab already has a Storage account, a Day 4 Service Bus Standard namespace/queue, and a Python Function queue consumer. The task was to extend that architecture without duplicating the namespace or touching the pre-existing Day 2 source edit.
- **Decision:** Create a Storage system topic with a system-assigned identity and an event subscription filtered to BlobCreated events in the existing incoming container. Deliver to the existing integration-events queue. Grant Azure Service Bus Data Sender at that queue scope. Configure 10 delivery attempts and a 1,440-minute event TTL. Leave the existing Function consumer unchanged.
- **Alternatives:** Direct Blob-to-Function coupling, a new custom topic, or a separate queue/namespace. Reuse of the Storage system topic and queue adds the least new infrastructure while separating event notification from durable work buffering.
- **Dead-letter decision:** Do not configure Event Grid Blob dead-lettering on the shared Storage account. The first subscription attempt failed with a managed-identity authorization error for the dead-letter endpoint; current guidance specifies Storage Blob Data Contributor at Storage account scope. That role is too broad for this shared account. A dedicated Storage account or a reviewed security decision is required before adding Event Grid dead-letter storage. Service Bus' own DLQ remains available.
- **Consequences:** Event routing uses managed identity with no secrets and one queue-scoped sender role. The existing Function continues message processing and Service Bus retry/dead-letter semantics. Event Grid retry is configured, but failures that exhaust retry or qualify as non-retryable can be dropped without an Event Grid dead-letter destination. Delivery metrics must be monitored; no deliberate delivery failure was tested.
- **Security:** Existing Day 4 namespace remains local-auth disabled. No Event Grid Storage data role was granted. The subject filter is restricted to incoming. Private endpoint delivery is not supported for this Event Grid managed-identity leg.
- **Cost:** No namespace or compute added. Event Grid Basic is operation-based and Storage/Function usage remains metered. Review current regional pricing and budget.
- **Revisit when:** A production dead-letter store is isolated, a second consumer needs fan-out, private networking constraints change, or measured event volume justifies a different tier.
